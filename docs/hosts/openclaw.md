# OpenClaw

## Support boundary

`@doppelganger/doppelganger-host-openclaw` implements a native OpenClaw plugin against the public OpenClaw plugin SDK. The package is private workspace source, not a published npm package. Its implementation target is `openclaw@2026.9.1`; the deterministic adapter, preparation, catalog, context, approval, cancellation, identity, reload, and disposal suites are repository evidence. A completed native installed-Gateway smoke result must be recorded in [Verification](../operations/verification.md) before treating the host/version pair as certified.

The supported profile is OpenClaw's ordinary embedded agent route where `before_model_resolve` runs before synchronous native tool construction and `before_prompt_build` receives a native `runId`. External harnesses, locked-model paths that bypass warmup, background/group ingress without an exact trusted actor route, context-engine replacement, arbitrary generated native tool names, and automatic committed-turn capture are unsupported.

OpenClaw is a direct in-process adapter. It owns one Composition Runtime root and one isolated Runtime Session per current native `(agentId, sessionKey, sessionId, workspaceRoot)` binding. A separately selected `actor` Host Extension resolves the exact configured route; `runtime-host` owns the one direct shared bridge. The adapter does not reuse OMP's child process or framed RPC transport, change OpenClaw source, or alter the DeepSeek Harness design.

## Prepare a finite plugin artifact

Preparation activates the selected Runtime Preset as trusted process code, applies normal user and project patches, snapshots its ordinary portable tool catalog, disposes the temporary Runtime Session, and writes a finite OpenClaw plugin artifact. It may therefore start any external services configured by the preset; it is not passive manifest inspection.

From this repository checkout:

```sh
npm exec --workspace @doppelganger/doppelganger-host-openclaw -- \
  doppelganger-openclaw-prepare \
  --output /absolute/path/to/openclaw-doppelganger \
  --home /absolute/path/to/doppelganger-home \
  --preset my-assistant \
  --workspace /absolute/path/to/project
```

The command also accepts repeatable `--root system:/absolute/path` or `--root user:/absolute/path`, comma-separated `--roots`, `--default-preset`, `--defaultless`, `--no-shipped-root`, `--no-user-root`, and `--actor`. `--actor` exists only for an actor-dependent preparation activation; actor identity is not written into the artifact and must be configured independently for runtime use. Repeatable `--host-extension <module>` imports exact trusted modules for `hostKind: "openclaw"`; repeatable `--enable-host-extension <id>` or `<id>=<JSON>` supplies the ordered prepared selection.

The output contains:

- `openclaw.plugin.json` with plugin ID `doppelganger`, the exact prepared native tool names, the closed plugin configuration schema, and startup activation metadata;
- `prepared-catalog.json` with the Runtime Preset ID, native/canonical mappings, descriptor contracts, and a SHA-256 fingerprint, but no process-local tool revisions, actor identity, credentials, or runtime state;
- `prepared-host-extensions.json` with API-compatible available IDs, ordered normalized default selection, bundled module file mappings, and a separate SHA-256 fingerprint, but no actor mappings, native session facts, credentials, or mutable adapter state;
- `host-extensions/` with static bundled imports for every explicitly admitted custom definition;
- `index.js`, which validates both embedded artifacts, statically imports the bundled Host Extension modules, and creates the native plugin through public package exports;
- a private `package.json` that references the private workspace host package and includes the bundled Host Extension directory.

Publication resolves the requested output, rejects a filesystem root, stages beside the destination with directory mode `0700` and file mode `0600`, and rejects a generated manifest larger than 256 KiB. The implementation rereads and validates every generated file before an atomic rename, preserves the prior output until the replacement is published, and attempts restoration if publication or backup cleanup fails. Preparation never installs or reloads OpenClaw. Use a dedicated artifact path, inspect it, and perform native installation as a separate operator action; do not point preparation at an actively managed OpenClaw install directory.

OpenClaw requires concrete manifest-declared names. Portable names map deterministically to `dg_` plus `.` replaced by `__`, and the resulting name must satisfy OpenClaw's 64-character limit. Duplicate mappings, unsupported schema semantics, and incompatible descriptors fail preparation. A later portable name, including an arbitrary tool generated by Dynamic Runtime Plugins, cannot become native automatically.

### MCP tools during preparation

MCP startup is `background` by default. A background Loader row can return before initial discovery, so preparation can legitimately omit tools that appear later. If the generated manifest must include initial MCP tools, the operator-owned MCP row must explicitly use `startupMode: await-ready` before preparation. The host package neither inspects MCP services nor rewrites that field. See [MCP tool import](../features/mcp-tool-import.md).

## Install the generated artifact

The current repository is private and publishes neither the host package nor the generated artifact. For source-checkout development, make the private host package resolvable from the artifact, then ask OpenClaw to install or link the generated directory through its normal plugin manager. The repository native smoke uses a local link at:

```text
<artifact>/node_modules/@doppelganger/doppelganger-host-openclaw
  -> <repository>/packages/host-openclaw
```

On Node.js 26, every private workspace TypeScript package's resolved realpath must remain outside any `node_modules` directory. Make each package resolvable only through its package-name symlink under the artifact's `node_modules`; do not physically copy raw TypeScript workspace package trees there. Otherwise Loader's direct package imports fail with `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`; the Jiti-loaded artifact entrypoint does not alter those downstream imports. This is a source-checkout layout constraint, not a claim that a compiled or published package exists.

After creating that source link, install the artifact separately:

```sh
openclaw plugins install /absolute/path/to/openclaw-doppelganger --link
```

Review OpenClaw's source, capability, and install-policy prompts rather than treating this private source as a published or trusted catalog package. Installation registers and enables the plugin, but the running Gateway must also receive configuration and may require restart. Inspect cold and live state separately:

```sh
openclaw plugins inspect doppelganger --json
openclaw plugins inspect doppelganger --runtime --json
openclaw gateway restart
```

## Native configuration

The OpenClaw entry is `plugins.entries.doppelganger`. Conversation-hook permission belongs to OpenClaw's host policy, not to the plugin's `config` object. A non-bundled installation requires `hooks.allowConversationAccess: true`; `allowPromptInjection` must not be `false` because context uses `before_prompt_build`.

```json5
{
  plugins: {
    entries: {
      doppelganger: {
        enabled: true,
        hooks: {
          allowConversationAccess: true,
        },
        config: {
          runtimePreset: "my-assistant",
          warmupTimeoutMs: 70000,
          contextTokenBudget: 8192,
          roster: {
            home: "/absolute/path/to/doppelganger-home",
            defaultRuntimePreset: null,
            roots: [
              { path: "/absolute/path/to/presets", trust: "user" },
            ],
            includeShippedRoot: true,
            includeUserRoot: true,
          },
          actors: [
            {
              agentId: "main",
              sessionKey: "agent:main:trusted-user",
              workspaceRoot: "/absolute/path/to/project",
              actorId: "trusted-user-id",
            },
          ],
        },
      },
    },
  },
}
```

Configuration is closed: unknown fields fail validation. `runtimePreset` is an explicit runtime selection and must equal the Runtime Preset embedded in the prepared artifact. Without it, normal roster precedence applies: project selection, user default, then the configured deployment default. OpenClaw's normalized plugin options are defaultless unless `roster.defaultRuntimePreset` is configured, so no winning selection leaves Doppelganger inactive while OpenClaw continues. Optional `hostExtensions` is an ordered array of `{ id, config? }` selections limited to IDs in `prepared-host-extensions.json`; an unknown ID fails warmup and requires artifact regeneration/restart rather than runtime module import.

`warmupTimeoutMs` defaults to 10,000 ms and accepts 100 through 120,000 ms. This is an adapter warmup deadline, not an MCP deadline or cleanup bound. An `await-ready` MCP server defaults to a 60,000 ms startup deadline, so the default OpenClaw warmup can expire first. Set the host warmup deliberately for strict-startup presets, while recognizing that failed startup cleanup may settle after both deadlines. OpenClaw may continue without Doppelganger after skipped, timed-out, or failed warmup; synchronous factories then expose no Doppelganger tools.

`contextTokenBudget` defaults to 8,192 and accepts zero through 1,000,000. A native per-request budget can only reduce this configured ceiling.

## Identity custody

Actor Identity is separate from Runtime Preset selection, Persona identity, and the actor-neutral Runtime Host bridge. Each `actors` row binds one trusted exact tuple of `agentId`, `sessionKey`, and normalized absolute `workspaceRoot` to one `actorId`. Duplicate `(agentId, sessionKey)` routes are rejected. When the prepared/runtime selection includes `actor`, its Host Extension resolves the current closed OpenClaw session facts against that mapping and provides bound or explicit unbound Actor Identity. Omitting `actor` leaves the provider absent while actor-independent protocols continue. A channel sender, project path, Persona field, model output, or first observed participant is never promoted into an actor binding.

The native `sessionId`, route, workspace, Host Extension selection, and actor mapping are replacement identities. If any changes, the adapter retires the previous binding before publishing another and stale tool closures fail. Runtime Preset HMR keeps the existing protected composition unchanged; in-session actor or Host Extension switching is unsupported.

## Capability profile

| Capability | OpenClaw behavior |
| --- | --- |
| Context | Per-turn resolution in `before_prompt_build`; instruction authority becomes system context and data authority becomes ordinary transient context. A native `runId` is required, and one assembly is reused for that run. Failure omits context rather than reusing stale data. |
| Tools | `session-start` delivery through a synchronous factory over the prepared finite name set. Every declared call must first pass native `before_tool_call`, which records the exact binding, native call ID, optional `runId`, native/canonical name, descriptor revision, and catalog generation for one later dispatch. Runtime catalog changes refresh compatible declared descriptors for later construction boundaries but invalidate prior-generation records and closures; they cannot enlarge the manifest or promise mid-loop replacement. |
| Required approval | Execute consumes every declared tool's pre-dispatch record exactly once and revalidates binding epoch, catalog generation, native and canonical name, exact descriptor revision, cancellation, and call identity, then forwards the captured `runId` when present. For an approval-required descriptor only, it additionally requires genuine `allow-once` and an exact digest match against the final cloned input. Ordinary non-approved tools may accept valid final arguments changed by native middleware. The pre-dispatch record alone is not an approval grant. |
| Cancellation | A native execution `AbortSignal` forwards call-correlated cancellation to the portable bridge. Binding disposal also cancels active calls and invalidates pending pre-dispatch records. Cancellation is cooperative and does not reverse completed external side effects. |
| Lifecycle | The advertised standard lifecycle set is empty. Reset, session end, runtime cleanup, and Gateway/plugin shutdown are ownership and disposal boundaries, not portable lifecycle publications. In particular, `turn-committed` is not synthesized. |
| Actor Identity | Explicit exact-route binding or explicit unbound state; no automatic sender-to-actor inference. |

Because `turn-committed` is unavailable, automatic candidate capture and Evolution completed-turn signal capture are unsupported on this adapter. Explicit memory, recall, proposal, and control tools remain ordinary prepared tools when composed.

Native `before_tool_call` participation is mandatory for every declared Doppelganger tool, including tools that do not require user approval. Direct invocation without the matching one-shot record, a wrong call ID, stale revision or catalog generation, replaced binding, cancellation, replay, or a required tool without `allow-once` fails before the portable bridge runs. Final-input digest equality is an authorization check only for approval-required tools; ordinary tools use the valid final native arguments after middleware.

## Catalog change and restart boundary

The adapter watches the selected authored composition and receives portable catalog revision hints. It validates the complete current snapshot and can withdraw unavailable, removed, revised, or contract-incompatible tools immediately. Existing stale closures fail exact revision and binding checks. A later native factory may use a compatible current descriptor only when its name and durable contract were already prepared. The prepared Host Extension module set and available IDs are a separate immutable artifact boundary; changing either requires regeneration and native restart.

Portable catalog revision strings are opaque, and a Loader-recreated registry may reuse one, so revision equality alone is not generation identity. Every complete projection increments an adapter-owned catalog generation; native tool closures and pre-dispatch records capture it, and a later projection invalidates both even when the opaque revision string repeats. Composition reload callbacks emit bounded failure diagnostics through the existing adapter diagnostic/logger path. If rejected reload rollback does not restore every composition entry to `active` or `disabled`, the adapter immediately clears the projection, marks and disposes the binding, and withdraws it rather than serving uncertain restored state.

Regenerate the artifact and restart or reinstall the native plugin when:

- a portable tool name is added or removed from the intended native surface;
- a prepared descriptor's schema, label, description, or approval contract changes incompatibly;
- the selected Runtime Preset differs from the prepared Runtime Preset;
- MCP discovery must add a name that was absent during preparation;
- a generated Runtime Plugin introduces a new arbitrary portable name.

Doppelganger never rewrites the installed manifest, mutates OpenClaw's registry after guarded registration closes, or exposes a universal dispatcher as a substitute.

## Disposal and recovery

`before_reset`, `session_end`, and OpenClaw runtime-lifecycle cleanup retire the matching binding. Retirement fences new work, forwards cancellation to active tool calls, cancels pending pre-dispatch records, clears per-run context, disposes the Runtime Session and owned Composition Runtime, and removes the route only after cleanup settles. Plugin-wide cleanup snapshots every binding, attempts all disposals, clears owned maps, and reports aggregate failures after reachable cleanup.

Warmup failure is contained to Doppelganger: the binding becomes failed and its direct activation is disposed, while OpenClaw may continue. Recovery is a fresh native binding or Gateway/plugin restart after correcting selection, trust, external-service, or catalog problems; a failed binding is not silently republished late.

To remove the integration, disable or uninstall `doppelganger` through OpenClaw's plugin manager and restart the active Gateway when required. This disposes native bindings but does not delete Runtime Presets, patches, feature-owned databases, MCP configuration, or other OMP/DSH deployments.

## Trust boundary

Preparation and runtime activation execute the selected Runtime Preset, Loader plugins, admitted Host Extension modules, generated Runtime Plugin source, and configured external commands with the process user's authority. `system` and `user` roots are authoring policy, not sandboxes. Host Extension API/version, exact-host, configuration, and closed-fact validation constrain composition errors but do not contain malicious installed code. The native OpenClaw plugin is trusted in-process code, while external Host Extension factories receive no OpenClaw gateway, node, subagent, sandbox, worktree, credential, provider, UI, or registry authority.

The operator owns the prepared tool catalog, admitted Host Extension package versions and module specifiers, normalized Host Extension selection, OpenClaw install provenance and capability consent, hook permissions, exact actor mappings, Runtime Preset roots and selection, external MCP commands/endpoints, credentials, and restart decisions.

## Primary implementation

- `packages/host-openclaw/src/cli.ts` — preparation CLI.
- `packages/host-openclaw/src/prepare.ts` — audited temporary activation and staged artifact publication.
- `packages/host-openclaw/src/catalog.ts` — deterministic names, schema compatibility, fingerprinting, and runtime projection.
- `packages/host-openclaw/src/plugin.ts` — synchronous native registration, hooks, tool factory, and cleanup.
- `packages/host-openclaw/src/adapter.ts` — binding, context, tools, approval, cancellation, diagnostics, and disposal.
- `packages/host-openclaw/src/host-extensions.ts` — exact-host module preparation, fingerprinted metadata, static runtime reconstruction, selection, and Actor Identity routing.
- `packages/host-openclaw/src/direct.ts` — direct Runtime Preset selection and Composition Runtime ownership.
